Lilia UI Overhaul Audit

Repository-wide static inventory of UI registrations, renderers, entry points, and UI-affecting network/event flows. Check an item when its interface has been reviewed or overhauled.

Audit Notes

Inspected: the complete repository file list, all Lua under gamemode/, shared/client/server/module/library/entity paths, core derma panels and skins, netcall files, command libraries, hooks, weapons, items, and supporting HTML/assets where UI behavior was referenced.

Patterns found: 57 custom vgui.Register panels; direct and indirect vgui.Create; DFrame/DPanel descendants; HUDPaint, DrawHUD, and overlay rendering; surface.*/draw.*; keybinds; console/chat commands; server-to-client net receivers; and module-specific UI registries/callback tables.

Static-analysis limits: Lua dynamic dispatch, generated command names, framework load order, permissions, runtime hooks, and external Garry’s Mod behavior cannot be proven from text alone. “Possibly Active” is used where registration or references exist but the final runtime path is conditional or dynamically indexed. “Unused” is reserved for registrations with no meaningful repository reference after name/function/file searches.

Runtime verification needed: exercise character selection, F1, inventory variants, vendor editing/trading, NPC/dialog/door flows, admin stick and admin panels, tickets/logs, chat, keybinds, spawn/config screens, notifications, and HUD overlays on a live client with representative permissions and server responses.

Suspicious areas: generic reusable controls such as liaHorizontalScrollBar, liaSlideBox, liaTabButton, liaMarkupPanel, and some legacy inventory/administration paths have weak or only indirect references; verify before removal.
